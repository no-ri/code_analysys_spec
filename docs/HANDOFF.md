### (1) F-16 の測定 — ②-a の的中率

**これを先にやるべき理由**: cJSON 66.5% / cmark 59.9% という比率は「**形の上で解けるはず**」を数えたもので、
**実際に正しい先を指しているかは一度も検証していない**。簡易版の価値の根拠がここに載っている。

準備は済んでいる。

- §8.5 が「ゴールデンデータは **cJSON に対してのみ**人手で作る」と決めている
- J-5 が突合キー `(file, start_line, start_col, kind)` と期待値（`dst_id` / `status` / `reason`）を定めた
- **I-1 でシンボルIDから `snapshot` を外したので、`dst_id` を期待値として書ける**

**そして F-11 が「この検証が要る」ことの実例になった（2026-08-31）。**
形の上で「解けるはず」と数えた C# の 335 件を追跡したら、**実際に解けたのは 180 件（53.7%）**だった。
**形での分類は約 2 倍に膨らむ。** ②-a に同じことが起きていない保証は無い。

**決めること**: A / B / C のどれで進めるか。

| 選択肢 | 中身 | 費用 | リスク |
|---|---|---|---|
| **A. いま測る** | cJSON 526 件にゴールデンデータを作り、②-a の的中率を出す | 人手の突合（②-a は 350 件） | 低い。**構想文書の数字が確定した根拠を持つ** |

| **C. 標本で測る** | 350 件から 50 件程度を無作為抽出して推定する | 小さい | 中間。傾向は掴めるが断定はできない |

| ID | 結論 |

| **F-12** | 53 / 55 / 56 は **53 ⊂ 55 ⊂ 56** で差は**3件**。**正しいのは 55（5.4%）** |

**F-10 が覆った理由**: E-1 の帰結文自身が「少なくとも**レシーバの型名からの近似**が要る」と条件を書いており、
改良B / C がその近似で、それが初版必須に入った。**矛盾ではなく、測定時点の構成が初版の構成ではなかった。**
ただし乗ったのは全呼び出しの **9.5%**（最大の 63 件を除くと 34 件）なので、
**図には集約前の `status` 分布を必ず添える**。

**F-12 が示した本当の問題**: 3件の差は「規則が違うだけ」ではなく、**2つとも誤り**だった。
53 は `{self, this, cls, super}` に **C# の `base` が無く** 2 件取りこぼし、
56 は `this.` / `base.` を**メソッドの存在確認なしに** `resolved` として `this.GetType()`（`System.Object`）を 1 件過大計上。
原因は**3つのスクリプトが同じ判定を別々に書き直していた**こと。
→ 実装では**判定規則を1箇所に置き、言語ごとに変えるのは集合の中身だけ**にする。

**F-11 の主因**: 「レシーバが型名（static）」を**識別子の先頭が大文字かだけ**で判定していた。

## 5. 環境メモ（実測済み・再確認不要）

- `sqlite3` は **Python 本体に同梱**。単体インストール不要
- **tree-sitter**: `pip install tree-sitter tree-sitter-language-pack` の**1コマンドで完了**。
  追加依存なし、C コンパイラ不要、計約 7.6MB、371言語対応、対象6言語すべて対応、MIT
- **tree-sitter の `Requires-Python`（2026-08-31 実測、F-15）**: `tree-sitter` 0.26.0 = **`>=3.10`**、
  `tree-sitter-language-pack` 1.15.8 = **`>=3.10`**（実行時依存は `tree-sitter>=0.23` の1つだけ）。
  → **軸1 の「Python 3.10+」は tree-sitter 自身の要求**であり、暫定値ではなく下げられない
- **tree-sitter のエラー回復**: 式の破損・未知のマクロ修飾からは**完全に回復**するが、
  **括弧の不均衡は後続を巻き込んで全滅**する（実測 0/3）
- **tree-sitter の速度**: 1.7MB / 20,000行の C を 0.77 秒。ただし**抽出は S 式クエリで書くこと**
  （Python 側で木を走査すると 2.37 秒 → クエリなら 0.26 秒、約9倍）
- **`#ifdef` は両枝が構文木に載る**。これは簡易版がフル版より強い領域でもある
  （フル版は1構成しかパースしないので Linux 上では `#ifdef _WIN32` の中身が見えない）
- `.ps1` は **UTF-8 BOM 必須**。`.gitattributes` で `.ps1` は CRLF、`.sh` は LF に固定済み
- **`--depth 1` の shallow clone では git の変更頻度が測れない**（全ファイル一律 1 件になる）。
  §8.4 の推奨セットはすべて shallow clone で取得している
